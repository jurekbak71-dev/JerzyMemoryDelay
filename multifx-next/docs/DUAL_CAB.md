# Dual guitar CAB 1.0.0

Separate `cab_dual` ABI 3 plugin; existing `cab` remains unchanged. Two independently loaded stereo IRs use the existing PFFFT convolver and original WAV decoder/resampler. No BassAmbient dependencies. Creation loads an asset JSON outside audio:

```json
{"ir_a":"/absolute/path/a.wav","ir_b":"/absolute/path/b.wav","dry_mode":"aligned"}
```

Either IR may be empty. `dry_mode` defaults to `aligned`; `legacy` is explicit migration support. Invalid modes and relative nonempty IR paths fail creation. Instance replacement loads fresh convolution/filter histories; loading and instance retirement belong to the host control path, never process().

Normalized parameter order: mix, blend, level, lowcut, highcut, enabled. Defaults: 1, 0, .5, .12, .85, 1. Blend is linear A/B with absent IR contributing zero, preserving original behavior. Gain is `10^((level*36-18)/20)`. HP frequency is `30*10^(lowcut*1.6)`, LP `1000*10^(highcut*1.45)`; original one-pole LP then subtractive HP per IR/channel. Coefficients update once per process call when cutoffs change, outside the sample loop. Parameters apply at process-call boundaries; sample offsets require host block splitting.

Latency metadata is 64 frames. Aligned mode delays all dry/bypass output 64 samples; legacy mode leaves dry undelayed, preserving original partial-mix comb behavior. Wet remains delayed 64 in both modes. Enable, bypass, mix and blend use per-IR weight slew limited to 1/64 per sample (at most 64 samples to a new normalized target). Initial weights start at zero. Level/filter changes are not smoothed.

Convolution and filters suspend once their current and requested IR weights are zero. Thus mix=0 / bypass stop work after the bounded fade; a zero-weight blend endpoint skips the unused IR. Histories and filter state freeze. Reactivation processes 64 samples to re-prime the input block before increasing wet weights. Existing A/B balance is retained while a newly requested IR primes; bypass reductions can proceed immediately. After priming the requested weights slew rather than unmuting at full weight. This is bounded reactivation, **not** continuous tail preservation: long historical tails can resume. No reset/allocation or unbounded catch-up occurs in process. Replacing the complete instance starts fresh histories; the host must manage graph transition fades if required. IR replacement is not an in-place parameter or audio operation.

Process performs no I/O or allocation/free; each convolver's existing storage is prepared at creation. Runtime allocation guard and hardware performance remain separate verification requirements. For allocation instrumentation, link next_dual_cab_test with next_alloc_guard and place jfx_test_reset()/jfx_test_rt(1) immediately around DualCab::process only, disabling the guard before assertions, file creation and constructors; verify allocation and free counters are zero. CMake registration: add src/dual_cab.cpp to next_cab_dsp; build cab_dual.cpp as a shared plugin linked with next_cab_dsp; link tests/dual_cab_test.cpp with next_cab_dsp. The test uses throwing checks (also active under NDEBUG), generated float WAVs, independent original filter formulas, all blend/mix endpoints and halves, gain endpoints/center, both dry modes, long-IR loading, fresh instances and finite toggling. A constant-input transition test toggles enabled, mix endpoints and blend endpoints and requires every successive output step after initial dry priming to remain below 0.1; the observed maximum was 0.015583. This bound applies to this specified fixture, not arbitrary IR gain/input signals. It does not establish hardware deadlines, inaudible transitions, all WAV formats, or hot-swap integration.
